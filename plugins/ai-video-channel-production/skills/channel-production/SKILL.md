# AI 视频频道生产系统总入口

进入内容主链前读取 [逐阶段确认契约](references/manual-stage-confirmations.md) 和 [用户审核文档规范](references/user-review-documents.md)。前者控制是否继续，优先于 bundled prompt 中关于“直接继续”或“不等待确认”的旧描述。用户可读审核文档、机器生产包和 YouTube 发布包必须分层保存，不能相互替代。

## 默认主线：先自由创作，后固定生产

每个新任务先调用 `content_workspace_start` 建立 `UNBOUND` 自由创作工作区。此阶段禁止为了找默认值而调用 `channel_list`、`channel_bind_task`、`content_project_start`，也禁止按标题、题材、文件名或相似内容读取旧频道、旧项目和旧学习记录。用户可以自由决定资料来源、临时提示词、执行顺序、是否联网、是否先写标题或先改正文；系统只执行用户实际要求的步骤，并把每个可确认结果保存为版本化文档。

内容阶段不是固定流水线。下面只是常见组合，不是必经顺序：

```text
任意资料／联网研究／用户临时提示词
→ 用户指定的分析、构思、写作、编辑、翻译或包装步骤
→ 用户逐项确认可用文稿、标题、简介、Hashtags、封面等结果
→ 用户明确“开始制作视频”
→ 选择频道＋确认制作设置＋选择唯一正式文稿
→ 整理并校验配音稿
→ 复用已确认素材，只补齐缺失发布素材
→ 工坊制作 → 发布中心
```

默认使用审核模式。用户一句话列出多个步骤，只代表本次任务范围；各结果确认后才成为后续有效输入。只有当前任务明确授权“自动完成剩余流程”时才连续执行。用户明确说“制作完成后自动上传”时，另调用 `content_workspace_auto_upload_authorize` 保存当前任务＋当前项目授权；最终中文验收卡照常展示，但不得再次询问同一上传决定。频道预设、旧项目和其他对话不能提供任何自动授权。

## 热点研究与文字创作路由

用户要求搜索某地区或某类受众的当前热点、趋势、新闻词汇或创作素材，并说明“选择后再写故事／小说／文案”时，固定先执行研究与选择，不得先进入生产设置：

1. 从用户原话提取已经明确的地区、受众和题材范围；不得重复询问或把它们包装成整张生产确认卡。
2. 立即交给 `$content-source` 联网取得公开证据，保存 `00_热点检索与创作素材选择.md`。每个 `H` 编号候选必须包含目标语言原词、中文解释、来源标题与可点击链接、发布日期或页面时间、采集日期、公开热度／趋势依据、置信度和可用于虚构创作的功能。
3. 只有选择卡已经真实生成并展示后才能说“检索完成”。没有链接、日期和证据的候选不得标为热点；证据不足时标记“待验证”，不得凭印象补齐。
4. 展示选择卡后停在 `R0_RESEARCH_SELECTION`，等待用户选择，不得同时生成小说、提示词或生产卡。
5. 用户选择后，只补问创作真正缺失的目标输出语言、篇幅／集数或其他内容边界，再执行选题或文字创作。用户只要文字成品时，整个任务都不需要配音、宫格、故事图片画风、图片提示词、视频提示词或镜头视频设置。

用户输入存在错别字、语音识别或多义表达时，只澄清真正影响当前步骤的最小问题。含糊项只影响后续步骤时，不得阻塞当前检索；在进入受影响步骤前用一个聚焦问题确认。不得把模糊的“提示词”擅自解释成“视频提示词”，也不得把“视频提示词”解释成实际生成视频。

## 链接与文本的意图优先级

1. 用户发送视频链接、文章链接、本地文件或正文，并说“下载字幕、取文案、导入资料”时，只执行 `$content-source`，保存完整规范正文及段落／时间证据索引后停止。
2. 用户只说“拆书、拆解文案、给仿写方向、完全仿写”，且没有提供当前任务提示词文件或已确认创作大纲时，说明旧内置 `content-deconstruct` 与旧方向推荐能力已移除；不得调用旧工具、旧提示词或旧项目方向。用户已经主动提供一份或多份提示词文件时，不适用这条拒绝规则，改走下方“当前任务临时提示词编排”。
   兼容说明：旧拆解入口仅作为“旧拆解已退役”的识别标记，不代表允许恢复旧能力。
3. 用户明确说“原创重构”或“本土化扩写”时，才允许进入独立素材研究模块；结果必须先保存并展示为用户可查看大纲，用户确认后才能交给 `$content-rewrite`。
4. 用户已经提供不少于 80 字、具备主线因果与结局边界的创作简报／故事大纲，并明确要求写正文时，走 `provided-outline` 路线交给 `$content-rewrite`，不再生成或要求仿写方向。
5. 多组选项使用互不冲突的编号，例如入口用数字、频道预设用字母。用户回复的编号不存在或可作多种解释时先澄清，不得静默换算。

## 路由

- 建立／进入频道资料库、修改频道默认值、备份恢复：`$channel-onboarding`。
- 当前热点、趋势、新闻词汇或联网创作素材选择：`$content-source` 取得可追溯公开证据，返回本 Skill 生成 `R0_RESEARCH_SELECTION` 选择卡；用户选择前不得开始写作。
- 视频链接、用户文件、粘贴文本、资料库检索或用户明确要求的公开联网资料：`$content-source`；取得来源后停止，不自动交给分析或方向生成。
- 只要求系统内置拆书、拆解、迁移／仿写方向：旧能力已移除，不路由到旧 Skill。
- 用户主动提供临时提示词文件并要求按顺序分析、构思、写作、审核或包装：使用 `content_workspace_prompt_register` 逐份登记，再按用户指定顺序执行；不得将提示词正文写进 Skills、插件资产、频道默认值或其他项目。
- 用户已经明确确认创作简报／故事大纲后的完整正文：`$content-rewrite`，固定使用 `provided-outline` 路线。
- 审稿、直接修改、复查和正式母稿冻结：`$content-review-edit`。
- 依据正式母稿生成标题、YouTube 简介和正式16:9封面：`$content-title-description`；`content-thumbnail` 只是该 Skill 的资产槽位，不是独立 Skill。
- 发布素材联合核验与汇总：`$publishing-assets`。
- 工坊制作、进度、失败重试、成片技术验收：`$production-handoff`。
- `VIDEO_READY` 后本地发布包与只读状态：`$publish-video`。
- 数据采集、报告与建议：`$data-center`。
- 系统更新：`$update-ai-video-system`。

## 状态与恢复

### 当前任务临时提示词编排

1. 仅接受用户在当前任务主动点名的 UTF-8 文本提示词文件。逐份调用 `content_workspace_prompt_register`，保存 `taskId + workspaceId + projectId + promptId + SHA-256 + 用途 + 执行顺序 + 字段映射`；不得复制提示词正文到任何 `SKILL.md`、`references/`、`assets/` 或长期频道规则。
2. 用途允许分析、构思、写作、审核、包装和自定义，不把流程写死为某一题材或固定四步。用户可增删提示词、调整顺序或指定“书名→YouTube标题、导言→YouTube简介”等字段映射；显式映射优先于系统对提示词字段名的猜测。
3. 已登记文件内容发生变化时，旧合同立即失效；使用新 `promptId` 重新登记并显示变化。合同不得跨任务、跨项目、跨频道或跨新对话复用。
4. 临时提示词可以控制本阶段的内容方法与输出格式，但不能覆盖来源事实边界、逐阶段确认、正式稿事实锁、制作设置确认、G6、OAuth、真实上传和删除审批。
5. 每个需要用户查看或后续复用的结果用 `content_workspace_document_save` 保存；用户确认时调用 `content_workspace_document_confirm`。文件名和步骤按本次创作需要决定，不强制先生成分析或大纲；但生成正式正文前仍必须有用户提供或确认的不少于 80 字创作简报／故事大纲。
6. 初稿非中文时同时保存 `04_仿写初稿_目标语言.txt` 与 `04B_仿写初稿_中文版.txt`。中文版只供用户审核，不进入配音、字幕或分镜。
7. 自由创作阶段的唯一可写状态位于工具返回的 `contentWorkspacesRoot`；开始制作后使用 `productionHandoffPath` 交接。不得把频道目录、旧项目目录或导出副本当作本次续写来源。
8. 用户确认某阶段后又要求修改时，先调用 `content_revision_begin`，范围只允许 `creative-plan`、`topic`、`manuscript` 或 `publishing`，并使用当前任务精确确认引用 `task:<taskId>:revise:<projectId>:<scope>`。旧版本保留供对照，受影响下游包立即失效；未取得该确认时标题、封面、工坊或发布阶段均不得反向改写正文和方案。

### 内容条件门与制作设置门

内容研究、题材推荐、选题、大纲、拆解、仿写、审稿、正式稿、标题、简介、Hashtags 和封面阶段，只确认目标地区、男频／女频／综合向定位、目标输出语言，以及当前内容真正需要的篇幅／集数策略。优先使用用户已经明确给出的值，只补问缺失或冲突项。不得因为配音、音色、宫格、故事图片画风、图片／视频提示词、成片方式或视频范围尚未确认而阻止内容创作与包装。

只有用户明确说“开始制作／进入工坊／移交制作”后，才允许查询频道并读取 [36 个图片风格预设](../../assets/image-style-presets.json) 和预扫描音色目录。先让用户选择频道号，再显示一张制作设置卡，统一确认：唯一正式文稿、配音引擎、声音模型、旁白音色、章节标题是否朗读、宫格批次、画幅、图片提示词开关、视频提示词开关、故事图片画风、成片方式、镜头视频范围，以及视频输入模式（仅首帧／首尾帧）。确认后调用 `content_workspace_bind_production`；频道预设和旧项目只能作为可见预选，不能替用户确认。只请求文字成品时不得显示这张卡。

制作绑定后调用 `content_workspace_narration_prepare`，把正式稿整理成能直接配音的文本。默认不朗读“第一章／Chapter 1”等结构标题；只有制作卡明确允许时才保留。随后读取工作区已确认文档：已确认的标题、简介、Hashtags、封面等直接复用，只生成缺失项，不得用旧项目素材覆盖本次结果。

制作设置卡必须使用独立 `S` 编号组，分组但完整展示 `visual_01`–`visual_36` 全部当前预设的编号与名称，并提供自定义入口。可以标注一个基于本项目题材与画面需求的推荐项及理由，但不得只显示推荐项。用户必须确认一个当前预设或一条非空自定义画风后才能移交；确认结果保存为 `image_style.preset_id` 与 `image_style.prompt`，并原样传入 `production-config.json` 与工坊生产包。已退役的 `gpt2_*`、`style_*` 和旧提示词不得显示或自动匹配；旧项目中的非当前提示词只能作为“自定义画风”显示。画风缺失只阻止生产包组装与生图，不得阻止选题、写作或包装。

视频输入模式默认使用 `first_frame`。只有用户在本次制作设置卡明确选择首尾帧时才写入 `frameInputMode=first_last_frame`、`endFrameSource=dedicated_generated`；它不自动开启视频提示词或实际视频生成。首尾帧模式对每个已选镜头独立生成同镜头尾帧，并把首帧、尾帧和该镜头的明确视频提示词一起提交。缺少尾帧、缺少明确视频提示词、模型不支持双参考帧或调用失败时必须暂停，不得静默降级为仅首帧或静态图。

视频提示词与实际生成镜头视频是两个独立开关，均为当前任务显式授权项，不能成为频道默认值，也不能从错别字、模糊“提示词”、旧项目、旧预设或其他任务继承。用户未明确要求视频提示词时写入 `videoPrompt.enabled=false`。用户没有明确要求实际生成视频及其镜头范围时，必须写入 `videoGeneration.enabled=false`、`selectionMode=none`、`count=0`、`fallbackPolicy=pause`；仅说“生成视频提示词”时实际视频仍保持关闭。只有用户明确指定“全项目前 N 镜”“每集前 N 镜”“全部分镜”或具体镜头后，才可在本次任务临时开启并传递绑定当前 `taskId` 的确认记录。

角色图、分镜图和宫格图固定使用 `storyImageTextPolicy=forbid_visible_text`。这类剧情图片禁止可读文字、字母、数字、字幕、对白气泡、标题、招牌内容、Logo、水印、签名和编号；文字载体只能呈现不可辨认的抽象纹理、空白表面或模糊符号。正式 YouTube 封面继续由标题／简介／封面阶段管理，可以使用用户已经确认的封面文案，不得把剧情图片无文字规则误用到封面。

1. 调用 `content_capabilities` 读取内容能力；标题、简介和封面都由同一 Skill 提供。
2. 自由创作工作区没有 `channelProfileId`。进入制作后才绑定一个目标发布频道；参考视频频道永远不能自动成为发布频道。
3. 只分短篇和长篇；长篇按检查点恢复，只补缺失章节，不用摘要代替正文。
4. 正式内容主链使用用户确认创作简报／故事大纲 → Topic Package／Rewrite Draft → Manuscript Package → Title/Description/Thumbnail Assets；Source Package 只在用户明确要求取材时独立保存，不再自动生成拆解包或方向包。
5. 每个用户需要查看或后续使用的结果都保存为可点击的版本化文档；不强制生成与本次任务无关的 `01`–`11` 文件。成片就绪后另在发布包中生成 `FINAL_CHINESE_REVIEW_CARD.md`。
6. 所有成功状态以持久化文件、Schema、确认记录和 SHA-256 为准。
7. 所有中心、所有阶段的确认卡统一使用“中文内容在前、目标语言原文在后”的双语结构；技术状态码保留，但不能用英文状态码代替中文解释。
8. 非中文正式稿在冻结前必须通过独立二次外语质量保险门；创作批次与审校批次分别标识，逐集检查语法、地区自然度、术语、习语、翻译腔、文化称谓、TTS 可读性和中文审核一致性。
9. 新任务不按相似度恢复旧项目，不默认加载频道学习或旧蒸馏结果；恢复与历史学习都必须由用户在当前任务明确选择。

## 安全边界

- 不读取或回显 Token、OAuth、Client Secret。
- 不根据标题、封面、简介或评论编造视频正文。
- 不绕过登录、付费墙、DRM、验证码或网站访问限制。
- 不逐句复制、近义词替换、改名换皮或拼接多个来源段落。
- 工坊、远端修改、OAuth、真实 Analytics 和长期频道学习继续遵守各自审批门。当前任务已明确授权自动上传时不重复要求最终上传确认；若无该授权，仍须在最终中文验收卡后等待确认。
