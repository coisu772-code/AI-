# 用户审核文档规范

自由创作阶段的文档写入当前 `content-workspaces/<workspaceId>/documents/`；进入制作后，由生产交接清单把确认版本映射到频道项目的 `用户审核文档/`。这些文件面向用户直接阅读；机器契约、JSON、版本、来源锁和 SHA-256 继续保留，不能用 Markdown 代替。下表是兼容旧生产包的常见文档角色，不代表每个自由创作任务都必须按编号生成全部文件。

| ID | 文件名 | 生成阶段 | 要求 |
|---|---|---|---|
| market-research | `00_热点检索与创作素材选择.md` | 按需联网研究 | 每个候选含独立编号、目标语言原词、中文解释、来源标题与链接、发布日期／页面时间、采集日期、公开趋势依据、置信度、事实边界和可迁移创作功能；展示后停在 `R0_RESEARCH_SELECTION` |
| source-analysis | `01B_内容分析与提示词执行结果.md` | 当前任务临时提示词分析 | 只在用户明确要求查看或确认分析结果时生成；记录提示词合同 ID、文件哈希、来源依据、分析结果和未知项，不复制提示词正文。提示词内部含分析步骤但用户只要正文时不生成 |
| creative-plan | `02_创作方案与大纲确认.md` | 创作方案 | 仅在用户明确要求查看、比较或确认创作方案／大纲时生成；形成唯一可执行故事方案、主要因果、人物功能和结局边界，确认后可按 `provided-outline` 写初稿。`direct-draft` 不要求本文件 |
| rewrite-draft-target | `04_仿写初稿_目标语言.txt` | 仿写 | 完整初稿，不以摘要或缩写代替正文；可来自已确认大纲，也可直接来自用户当前 `direct-draft` 请求 |
| rewrite-draft-zh | `04B_仿写初稿_中文版.txt` | 仿写 | 非中文初稿的完整中文审核版；只供用户查看，不进入生产 |
| editorial-review | `05_编辑审核报告.md` | 审核 | P0–P3、位置、问题、建议、处理状态和影响范围 |
| revision-log | `06_修改记录与前后对照.md` | 审核 | 重要修改逐条记录位置、修改前、修改后、原因和影响 |
| final-script-target | `07_正式稿_目标语言.txt` | 正式稿 | 唯一允许进入配音、字幕和分镜的目标语言稿 |
| final-script-zh | `08_正式稿_中文版.txt` | 正式稿 | 与目标稿逐行对应；仅供审核，禁止进入生产 |
| packaging-bilingual | `09_标题简介标签_双语审核.md` | 包装 | 六个标题候选、正式标题、简介、Hashtags及中文翻译 |
| thumbnail-review | `10_封面候选与选择结果.md` | 包装 | 五张候选、封面短文案中文含义、检查、评分和正式选择 |
| production-overview | `11_完整生产资料总览.md` | 制作移交 | 配音文本、角色形象、音色、分集、工坊文件、发布信息和生产设置 |
| codex-visual-plan | `11B_Codex角色设计与分镜提示词方案.md` | 制作移交 | 漫画角色设计、身份锚点、逐镜表演、图片提示词及已启用的视频提示词；只供查看与执行对照 |

每次更新同一文档都生成版本记录；只有用户确认的当前版本能成为后续输入。索引保存语言、版本、路径、大小、SHA-256、更新时间、用途和来源绑定，并返回可点击绝对路径。不得新建、确认、复制或要求 `source-summary`／`01_原始素材说明.md`，也不得把它作为创作方案、正文、包装或制作的来源引用与质量门；必要的来源元数据只保留在机器来源合同或用户实际要求的分析文档中。旧项目已有的 `01_原始素材说明.md`、`02_完整拆解报告.md` 与 `03_迁移方向选择.md` 仅作为历史文件保留，不再成为任何新版本的输入或门槛。自由创作阶段只要求本次实际使用的文档，不得因缺少未请求的编号文件阻塞；开始制作时必须至少选定并确认唯一正式文稿，其余标题、简介、Hashtags、封面等按“已确认则复用、缺失才生成”处理。

用户明确要求直接成稿时，正文初稿就是本次第一个用户审核结果。不得为了满足旧文件编号或旧流程顺序先创建分析、方向、创作方案或大纲；附件内的内部写作步骤不改变这一点。被用户否决或标记为旧模板的未确认文档不得成为新稿来源。

自由创作工作区的 `workspace-state.json` 必须保持 `taskId + projectId + workspaceId` 唯一绑定；制作后的 `index.json` 再绑定 `canonicalProject.projectRoot`、当前状态、活动包哈希和失效次数。工具外另建的同名目录只能作为只读导出，禁止继续写入或作为下游来源；状态不一致时必须阻止制作和发布。

`00` 是可选的研究选择卡，只在用户明确要求当前热点／趋势／新闻词汇研究时生成。没有链接、时间和公开依据时不得登记为完成；它不创建 Production Package，也不要求频道、配音、宫格、图片／视频提示词或故事图片画风。

目标语言为非中文时，中文版严格保持分集、`lineId`、顺序、说话人、旁白／对白类型和情绪一一对应。目标语言为中文时，中文版可以复用同一正文内容，但仍作为用户审核文件登记。中文版、中文标题翻译、中文简介翻译和 Hashtags 中文含义都不得写入 YouTube 正式发布字段。

进入制作后必须从用户确认的正式文稿确定性生成唯一配音稿，并与 Production Package 的 `script_lines.json` 绑定同一组目标语言行；默认移除不会朗读的章节结构标题。中文版始终只供审核，不得进入配音。任一来源版本、语言、用途或哈希不一致，必须阻止制作移交。

所有确认卡统一使用“中文优先＋目标语言对照”：中文区必须解释用户要判断什么，目标语言区保留将进入配音或 YouTube 的正式文本，技术状态码放在末尾。非中文正式稿另保存独立二次审校的 `foreign-language-quality-gate.json`，但该机器记录不能替代 07–08 正式稿供用户阅读。

用户审核文档、工坊生产包和 YouTube 发布包保持分离：

- 用户审核文档用于查看与确认；
- Production Package v2.1 继续包含目标语言配音文本、角色形象锚点、音色、分集、生产配置和正式发布素材；为兼容既有工坊界面可保留 `titleZhTranslation`，但不包含中文版长稿、中文简介或标签审核译文；
- YouTube 发布包接收成片、正式封面、目标语言标题、简介、Hashtags和发布设置，并额外携带仅供审核、明确禁止用于上传替换的 `FINAL_CHINESE_REVIEW_CARD.md` 与 JSON 数据卡。该卡在真实上传前集中展示故事、包装、封面文案、配音、频道、隐私状态和上传策略。

审核模式与自动模式使用同一套文档。自动模式可以在展示后继续，但不得省略 `04` 初稿、`07` 正式生产口播稿、`08` 中文审核稿或其他阶段文档的路径与哈希。
