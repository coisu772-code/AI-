# 文案仿写

只生成一个完整方案，不提供 8 个方向、TOP3 或重复选题门。用户没有指定模式时：只有一个主要来源使用模式一；明确要求结合资料、资料库或搜索时使用模式二。

## 模式一：单一来源高贴合仿写

使用 `sourceMode=direct-rewrite`。保留对标文已验证的：

- 目标受众体验、题材赛道和核心承诺；
- 总体篇幅范围、宏观框架、信息顺序和段落功能；
- 开场速度、钩子密度、情绪曲线、回报节奏、叙事视角与表达气质。

必须重建：作品名、人物、关系细节、背景、世界参数、具体事件、因果链、线索、冲突解决、高潮实施和结局后果。不得逐句改写、近义词替换、改名换皮或连续照搬完整事件顺序。

## 模式二：资料融合仿写

使用 `sourceMode=synthesis-rewrite`。可以组合资料库、用户上传资料和用户明确要求的公开联网研究。所有资料必须先经 `$content-source` 形成来源锁，再经 `$content-deconstruct` 独立拆解。

为每个来源记录 `role`：例如结构、事实、人物功能、世界机制、表达、案例或观众回报。权重表示参考优先级，不表示按段落拼接比例。最终只建立一个主角目标、一个统一因果引擎、一套人物关系、一条情绪主线、一个高潮和一个完整结局。

## 生成单一方案

1. 调用 `content_capabilities`，再校验 Content Deconstruction Package v1 和全部来源哈希。
2. 调用 `content_project_start`，按模式使用 `direct-rewrite` 或 `synthesis-rewrite`。
3. 生成一个完整候选：受众、语言、核心卖点、故事事实、世界规则、人物与关系、完整大纲、逐集剧情、精确篇幅、预计时长、集数、制作建议和包装扩展简报。
4. 记录 `sourceTransformationMap`：逐项写明来源功能、保留功能、新实现、新因果和原创边界。
5. 调用一次 `content_topic_checkpoint`，再调用 `content_topic_finalize` 冻结唯一 Topic Package v1。用户明确提出“仿写并输出”时，该明确请求可作为这一唯一方案的本次确认来源，不再要求从不存在的候选菜单中二次选择。
6. 运行 `content_integrity_check`。

用户要求“直接生成可制作文本”时，立即调用 `$production-text`。质量门见 [references/rewrite-gates.md](references/rewrite-gates.md)。

## 边界

- 不生成标题、简介或封面；只写入三个后续扩展的事实简报。
- 不把网络资料中的推断写成事实，不使用正文没有兑现的流量承诺。
- 不启动工坊、上传、Analytics 或长期频道学习。
