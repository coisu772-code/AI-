# 直接成稿或按确认大纲生成正文

旧拆解与方向能力已移除；本 Skill 只执行当前任务的直接成稿合同、确认大纲或 `task-prompt-guided` 外部提示词合同。

先完整阅读 [逐阶段确认契约](../channel-production/references/manual-stage-confirmations.md) 和 [用户审核文档规范](../channel-production/references/user-review-documents.md)。本 Skill 不执行旧式方向推荐；`direct-draft` 在写作批次内部完成必要构思，`provided-outline` 只把用户已经提供或确认的方案写成正文。

## 唯一入口

1. 只读取当前 `workspaceId` 中用户本次确认的来源、当前用户消息、用户提供或确认的大纲，以及当前工作区登记的外部提示词。文件名不要求是 `02_创作方案与大纲确认.md`。
2. `direct-draft`：用户明确要求直接生成一篇或多篇完整正文，并已提供完整参考正文、有效临时提示词、明确题材，或明确把具体创作决定交给系统时，当前消息就是写作授权。把语言、数量、长度、参考范围、禁用项和必须保留项整理成内部执行简报，直接生成初稿；不得把内部简报另存为创作方案后要求用户确认。
3. `provided-outline`：用户明确要求按大纲写作时，创作简报／故事大纲必须由用户在当前任务提供或确认，正文不少于 80 字，并明确主角、核心目标或困境、主要因果推进和结局边界。
4. 热点研究或原创重构结果只有在用户看过并确认后，才能作为 `providedOutline`。Source Package、视频标题、简介、关键词、旧拆解包、旧迁移方向和旧 8 方向结果都不能冒充用户大纲；但当前任务完整来源可在用户明确要求直接成稿时作为 `direct-draft` 的参考输入。
5. 用户只提供链接或原文并说“拆解、给仿写方向”，却没有要求写完整正文、没有当前任务提示词合同也没有确认大纲时停止，说明旧内置能力已移除。用户已经明确要求“写一篇完整文章”时不得误判为方向请求。
6. 新任务不得读取旧项目的 `Content Deconstruction Package`、`Writing Style Contract`、`selectedDirectionId`、`activeVersionId` 或任何历史方向记录。用户否决、要求作废或指出“旧模板”的未确认方案也必须排除。

## 生成与保存

1. 调用 `content_workspace_get`，确认工作区仍为 `UNBOUND` 或尚未被内容修改失效；不得调用 `channel_list`、`content_project_start`、`content_topic_checkpoint` 或 `content_topic_finalize`。
2. 按当前路线生成唯一完整正文：`provided-outline` 忠实执行当前确认大纲；`direct-draft` 依据当前请求、当前来源和有效提示词在同一写作批次内完成原创构思与正文。临时提示词按 `executionOrder` 和 `fieldMappings` 执行，只控制本次内容方法与输出格式，不得扩张用户要求的交付步骤。
   提示词正文始终留在用户原文件，不复制进本 Skill、频道规则或安装包。
3. 按用户本次要求创作完整正文；只分短篇与长篇，不得压缩成摘要或套固定章数。
4. 调用 `content_workspace_document_save` 保存目标语言全文；外语项目另存完整中文版。文档 ID 和标题反映实际用途，不强制旧编号。中文版只供用户审核，不进入配音。
5. 展示文档绝对路径、版本和 SHA-256。审核模式等待用户用 `content_workspace_document_confirm` 确认当前版本；只有用户明确要求继续编辑时才交给 `$content-review-edit`。

`direct-draft` 直接进入 `D4_REWRITE_DRAFT`。只有用户实际要求查看分析、方向或大纲时才进入 `D2_TASK_PROMPT_ANALYSIS` 或 `D3_TOPIC`；提示词文件内部写着“先分析”本身不构成用户可见确认门。

## 写作边界

- 忠实执行用户确认的大纲，但重新组织具体表达，不逐句复制来源正文。
- 不读取或恢复已退役拆解、迁移方向、8 方向仿写、旧提示词示例或其他项目候选。
- 不从系统高频职业、灾难、豪门、遗产、认亲或“被轻视后公开打脸”模板自动补剧情；每篇新稿的具体因果必须从本次来源功能与当前用户边界重新生长。
- `provided-outline` 不擅自新增改变主线的世界机制、主要关系、核心冲突或结局；必要缺口先询问用户。`direct-draft` 已由用户授权系统完成这些原创决定，只在真正缺失且不同答案会实质改变成品时澄清。
- 不生成正式标题、简介、Hashtags 或封面。
- 不启动工坊、上传、Analytics 或长期频道学习。
- 正式稿或发布素材已经冻结后，用户要求局部修改时先调用 `content_revision_begin`，确认引用必须精确匹配当前任务、项目和范围；只重做受影响文档与下游包，不得静默覆盖旧版本。
